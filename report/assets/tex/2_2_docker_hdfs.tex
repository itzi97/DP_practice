\subsection{Deploy HDFS}
\label{sec:2_2_docker_hdfs}

\par
For HDFS I reused the container setup from Data Processing class, as it comes
with a \texttt{Dockerfile} based on \texttt{apache/hadoop:3.3.6} and a startup
script \texttt{start-hdfs.sh} that handles the configuration and starts the
NameNode, DataNode, and SecondaryNameNode in pseudo distributed mode. I copied
both files into \texttt{docker/hdfs/} (\cref{fig:2-2-hdfs-dockerfile}):

\begin{figure}[H]
	\centering
	\includegraphics[width=0.9\textwidth]{2_2_hdfs_dockerfile.png}
	\caption{HDFS build context: \texttt{Dockerfile} and \texttt{start-hdfs.sh}}
	\label{fig:2-2-hdfs-dockerfile}
\end{figure}

\par
I then added the HDFS service to \texttt{docker-compose.yml}, pointing
\texttt{build} to the local \texttt{./hdfs} context so Docker builds the image
from those files (\cref{fig:2-2-compose-hdfs}):

\begin{figure}[H]
	\centering
	\includegraphics[width=0.9\textwidth]{2_2_compose_hdfs.png}
	\caption{\texttt{docker-compose.yml} with HDFS service added}
	\label{fig:2-2-compose-hdfs}
\end{figure}

\par
Started it up and verified both MongoDB and HDFS were running (\cref{fig:2-2-hdfs-up}):

\begin{figure}[H]
	\centering
	\includegraphics[width=0.9\textwidth]{2_2_hdfs_up.png}
	\caption{HDFS and MongoDB containers running}
	\label{fig:2-2-hdfs-up}
\end{figure}

\par
To make sure HDFS came up correctly I opened the NameNode WebUI at
\texttt{http://localhost:9870}. It shows the NameNode status, active DataNodes,
and filesystem capacity, everything looked good (\cref{fig:2-2-hdfs-webui}):

\begin{figure}[H]
	\centering
	\includegraphics[width=0.9\textwidth]{2_2_hdfs_webui.png}
	\caption{HDFS NameNode WebUI at \texttt{http://localhost:9870}}
	\label{fig:2-2-hdfs-webui}
\end{figure}
